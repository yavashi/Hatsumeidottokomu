## 1. ビジョン & コアコンセプト
- **サービスの本質**: 個人発明家の発明を紹介・保存するWebサービス。最終的には「日本中の個人発明を集めて、一般の人が発見できるようにする発明アーカイブ（図鑑・博物館）」を目指す。
- **デジタルアーカイブとしての価値**: 発明家が生涯で1〜2作品しか作らなくても価値がある。本人が亡くなった後も（料金が支払われる限り）デジタルアーカイブとして作品と人生の記録を後世（家族や一般ユーザー）に残し続ける。
- **AIによる半自動生成**: 自分でWebページを作れない高齢者・個人発明家のため、AIとの対話等を通じて紹介ページを半自動で生成し、運営側の一つの集合サイトに掲載する。
- **発明家同士のコミュニティは作らない**: 強い個性による人間関係トラブルのリスクを避けるため、発明家同士の掲示板、チャット、DM機能などは一切作らない。「発明家 → 発明作品 → 一般ユーザー・企業」という一方通行＋フィードバック（いいね、商品化希望ボタンなど）の構造を徹底する。
- **収益化構想（マネタイズ体系の刷新）**:
  - 【A】フリーミアム＋基本掲載料: 1作品は永久無料。2作品目以降または企業向け機能開放で月額550円＋作品110円。
  - 【B】生涯・永久アーカイブ保存パック（買い切り型）: 月額カード決済が死後停止するリスクを解消するため、一括買い切り（29,800円〜）で永久保管＋QR付きアクリル記念盾を家族に送付。
  - 【C】企業向け有料検索・仲介: 新商品候補を探す企業向け月額SaaS、ライセンス仲介（成功報酬15〜20%）、試作3D/図面製作受託。
  - 【D】需要データの精緻化: 「商品化されたら欲しい」投票時に希望購入価格帯と通知希望メールを取得し、企業への信頼性あるデータとして提供。
- **法的ガードレール（特許法第29条・新規性喪失の防止）**:
  - 特許・実用新案の出願前に公開すると新規性を失い権利化できなくなる重大リスクを防止するため、AI登録時に特許ステータスを事前確認し、未出願作品には強い警告・同意と非公開保管モードを提供する。

## 2. SDD基本原則 (Spec-Driven Development Core Principles)

### 原則 1: 仕様書が唯一の真実の源 (SSOT: Single Source of Truth)
- コードは仕様書の具現化に過ぎない。
- すべての実装・変更は、まず `specs/` 配下の仕様書に定義・反映してからコードに落とし込む。

### 原則 2: 生きた仕様書 (Living Specs) と頻繁な仕様変更への適応
- ユーザーのアイデアや思いつきによる方針転換を歓迎し、仕様の変更に即座に追従する。
- 仕様変更が発生した際は：
  1. 影響範囲を素早く特定し、該当する仕様書の差分（Delta）を更新する。
  2. 不要になった旧コードや古いモックデータは躊躇なくクリーンアップし、技術的負債やデッドコードを残さない。
  3. 呼称や仕様にはステータス（`draft`, `active`, `deprecated`, `completed`）を明記する。

### 原則 3: 高いモジュール性と疎結合性 (Loose Coupling)
- 仕様変更の波及効果を最小限に抑えるため、機能・UIコンポーネント、データ構造、ページを独立したモジュールとして設計する。
- 一つの画面や仕様の思いつき変更が、他の無関係なコンポーネントを壊さないアーキテクチャを維持する。

### 原則 4: 実行時検証の徹底 (Runtime Verification)
- 実装後は必ず静的解析（`npm run lint`）、ビルド確認（`npm run build`）、およびUI挙動の整合性を確認する。
- 「動かないコード」を放置しない。

## 3. 技術スタック & 開発標準
- **Framework**: Next.js 16 (App Router)
- **Runtime / Language**: React 19 / TypeScript (Strict mode)
- **Styling**: Tailwind CSS v4
- **Icons**: Lucide React
- **Directory Structure**:
  - `src/app/`: 画面ルーティング（App Router）
  - `src/components/`: 再利用可能なUIコンポーネント
  - `src/data/`: モックデータ（実DB移行前のスキーマ検証用）
  - `src/types/`: TypeScript型定義（仕様書のデータモデルと同期）
  - `specs/`: SDD仕様書・設計書・タスク管理

## 4. 仕様ライフサイクル
1. **Draft (構想・思いつき)**: ユーザーの新しいアイデア・実験的な仕様。
2. **Active (開発・適用中)**: 現在実装中、またはプロダクトで稼働している正規仕様。
3. **Completed (実装検証完了)**: コード実装・テストが完了し、安定稼働している状態。
4. **Deprecated (廃止・置換)**: 方針転換により取り下げられた仕様。必要に応じて `specs/archive/` に退避。
